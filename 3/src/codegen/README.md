# Модуль генерации кода (codegen)

Модуль разделён на несколько файлов для улучшения читаемости и поддержки кода.

## Архитектура

Генератор кода работает на уровне **CFG (Control Flow Graph)** - графа потока управления.

### Текущая реализация (гибридная)

Код спроектирован для работы с правильным CFG, где каждая операция = отдельный блок.

**Ключевые принципы:**
- Генератор проходит по всем блокам CFG
- Для каждого блока генерируется код операции
- Переходы между блоками основаны на **successors**:
  - 0 successors: конец функции (RET будет добавлен позже)
  - 1 successor: безусловный переход (JMP)
  - 2+ successors: условный переход (CMP + условный JMP + безусловный JMP)

**Для условных блоков** (блоков с 2+ successors и операцией сравнения):
```
successors[0] = default successor (false-ветка)
successors[1] = conditional successor (true-ветка)
```

Пример генерации для `if (a > b)`:
```asm
CMP a, b
JG true_branch     ; conditional successor (если a > b)
JMP false_branch   ; default successor (иначе)
```

### Будущие улучшения

Когда CFG будет полностью разбит на атомарные операции (каждое сравнение, присваивание, вызов = отдельный блок), текущий код будет работать ещё эффективнее.

## Структура модулей

### register_allocator
- `register_allocator.h/c` - Управление аллокацией регистров виртуальной машины
- Функции:
  - `allocate_register()` - выделение свободного регистра
  - `free_register()` - освобождение регистра
  - `free_all_registers()` - освобождение всех регистров

### function_context
- `function_context.h/c` - Контекст генерации кода функции
- Структуры:
  - `LocalVarMapping` - маппинг локальных переменных на регистры/стек
  - `ArgumentMapping` - маппинг аргументов функции
  - `FunctionContext` - контекст генерации кода для функции
- Функции:
  - `create_function_context()` - создание контекста
  - `free_function_context()` - освобождение контекста
  - `get_variable_register()` - получение регистра для переменной

### expression_gen
- `expression_gen.h/c` - Генерация кода для выражений
- Функции:
  - `generate_expression()` - генерация кода для AST-выражения
- Поддерживает:
  - Литералы и идентификаторы
  - Бинарные операции (+, -, *, /, <, >, ==)
  - Вызовы функций

### statement_gen
- `statement_gen.h/c` - Генерация кода для простых операторов
- Функции:
  - `generate_statement()` - генерация кода для AST-оператора
- Поддерживает:
  - Присваивания (`=`)
  - Вызовы функций
  - Объявления переменных
- **Упрощён**: не содержит логики обработки if/while (это делается через CFG successors)

### function_gen
- `function_gen.h/c` - Генерация кода функций и главная точка входа
- Функции:
  - `generate_function_code()` - генерация кода для одной функции
  - `generate_code()` - главная функция генерации кода (точка входа)
  - `generate_block_operation()` - генерация кода для операции в блоке
- Генерирует:
  - Пролог функции (setup stack frame)
  - Код базовых блоков CFG
  - Метки для каждого блока
  - Переходы между блоками на основе successors:
    - 0 successors: конец функции
    - 1 successor: безусловный переход (JMP)
    - 2+ successors: условный переход (CMP + JG/JL/JE/JNE + JMP)

## Использование

```c
#include "codegen.h"

// Главный заголовочный файл подключает все модули
VMProgram *program = generate_code(cfgs, cfg_count);
```

## Зависимости

Модули организованы в иерархическом порядке:
```
register_allocator (базовый, 24 строки)
    ↓
function_context (использует register_allocator, 91 строка)
    ↓
expression_gen (использует function_context, 87 строк)
    ↓
statement_gen (использует expression_gen, 55 строк) ← упрощён!
    ↓
function_gen (использует statement_gen + expression_gen, 157 строк)
```

## История рефакторинга

### Этап 1: Разделение на модули
- Разбит monolithic файл codegen.c (~600 строк) на 5 модулей

### Этап 2: Упрощение логики (CFG-based approach)
- **До**: statement_gen содержал явную логику обработки if/while/do (250 строк)
- **После**: statement_gen только обрабатывает простые операции (55 строк)
- **Почему**: Логика управления потоком теперь в CFG successors, а не в AST
- **Результат**: Код стал проще, понятнее и соответствует стандартной архитектуре компилятора
