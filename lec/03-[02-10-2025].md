# Лекция 2 октября 2025

Какое-то дерево разбора

чето про парсеры

походу компиляторы

программы состоят из алгоритмов и данных


## Лаба (номер 2)

требования

1. нет статичности (допускать создание множества экземпляров
2. нет магическим константам (либо вычислять либо задавать аргументом или конфигом
3. нет бесконечным циклам
4. нет утечке ресурсов
5. нет неожиданным завершениям программы (все завершать в результате выполнения, не аборт экзит)
6. нет побайтовому вводу выводу

рекомендуется:
- подготовить окружение разработчика (отладчик и пр)
- сборку осуществлять с помощью мейкфайла
- следовать принципам

отчёт:
1. титульник
2. цели
3. задачи
4. описание работы (описание созданной программы, состав модулей, способов использования, примеры вх и вых)
5. аспекты реализации (созданной программы, особенности алгоритмов, примеры кода)
6. результаты (что сделано по пунктам)
7. вывод (что достигнуто)

## Задание 1

Использовать средство синт анализа по выбору, раелизовать модуль для разбора текста в соответствии с языком по  варианту. Реализовать построение дерева с узлами по исходному файлу с текстом.

Вывести дерево "в формате поддерживающем просмотр граф. представления" (напр текст или dgml или .dot)

Порядок выполнения

1. изучить средство синт анализа (напр. бизон, антлр)
    a. должно поддерживать интерфейс совместимый с си
    b. должно параметризоваться спецификацией, описывающей структуру языка
    c. средство может функционировать посредством кодогенерации и/или подключения необходимых библиотек
    d. средство может быть реализовано с нуля, но тогда надо использовать обобщённый алгоритм управляемый спецификацией
2. изучить синтаксис разбираемого языка, записать спецификацию для конструкций
    a. подпрограммы со списком аргументов и возвращаемым значением
    b. операции контроля потока управления (ifelse циклы аналоги)
    c. в зависимости от варианта определение переменных
    d. целочисленные строковые и односимвольные литералы
    e. выражения численной битовой и лог арифметики
    f. выражения над одномерными массивами
    g. выражения вызова функции
3. реализовать модуль использоующий средство синт анализа для разбора языка по варианту
    a. программный интерфейс модуля должен принимать строку и возвращать структуру оисывающую соответствующее дерево разбора и коллекцию сообщений об ошибке
    b. результат работы модуля - дерево разбора - должно содержать иерархическое представление для всех синт конструкций включая выыражения представляющие собой иерарх. орг. данные, даже если на уровне средства синт. анализа для их разбора было использовано лин. представление
4. Реализовать тестовую программу для демонстрации работоспособности созданного модуля чтения и анализа, имя выходного файла записи для дерева, описывающего синт структуру разбранного текста
    a. через аргументы ком строки программа принимает имя вх. файла для чтения и анализа, имя выходного файла записи для дерева, опичсывающего синт структуру разобранного текста
    b. сообщение об ошибке должны выводиться тестовой программой (не самим модулем анализа)
5. результаты в отчёт
    a. в части 3 описание структур, представляющих результат разбора
    b. в части 4 описать какая доп обработка потребовалась для результата разбора, предоставляемого средством синт анализа, чтобы сформировать руз работы модуля
    c. в части 5 привести примеры исх анализируемых текстов для всех конструкций языка и соотв. результаты разбора

Вариант 1

Общая часть

```
identifier: "[a-zA-Z_][a-zA-Z_0-9]*"; // идентификатор
str: "\"[^\"\\]*(?:\\.[^\"\\]*)*\""; // строка, окруженная двойными кавычками
char: "'[^']'";
// одиночный символ в одинарных кавычках
hex: "0[xX][0-9A-Fa-f]+";
// шестнадцатеричный литерал
bits: "0[bB][01]+";
// битовый литерал
dec: "[0-9]+";
// десятичный литерал
bool: 'true'|'false';
// булевский литерал
list<item>: (item (',' item)*)?; // список элементов, разделённых запятыми
```

не общая часть

```
source: sourceItem*;
typeRef: {
    |builtin: 'bool'|'byte'|'int'|'uint'|'long'|'ulong'|'char'|'string';
    |custom: identifier;
    |array: typeRef '[' (',')* ']';
};
funcSignature: typeRef? identifier '(' list<argDef> ')' {
    argDef: typeRef? identifier;
};
sourceItem: {
    |funcDef: funcSignature (statement.block|';');
};
statement: {
    |var: typeRef list<identifier ('=' expr)?> ';'; // for static typing
    |if: 'if' '(' expr ')' statement ('else' statement)?;
    |block: '{' statement* '}';
    |while: 'while' '(' expr ')' statement;
    |do: 'do' block 'while' '(' expr ')' ';';
    |break: 'break' ';';
    |expression: expr ';'
};
expr: { // присваивание через '='
    |binary: expr binOp expr; // где binOp - символ бинарного оператора
    |unary: unOp expr; // где unOp - символ унарного оператора
    |braces: '(' expr ')';
    |call: expr '(' list<expr> ')';
    |indexer: expr '[' list<expr> ']';
    |place: identifier;
    |literal: bool|str|char|hex|bits|dec;
};
```

Это синтаксическая модель, не граматика

это надо переписать в формат выбранной тулзы
